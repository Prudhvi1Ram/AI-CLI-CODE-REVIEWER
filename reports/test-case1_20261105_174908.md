# Code Review Report: test-case1.py

**Overall Status:** Critical

## Summary

The function contains a critical logical bug where the return values are swapped relative to the condition check. Additionally, the code lacks input validation and type hints, which may lead to runtime errors or confusion.

## Findings

### 1. Logic

- **Severity:** Critical
- **Line:** 2

**Issues:**

- The condition 'num % 2 == 1' identifies odd numbers, but the function returns 'Even'. Conversely, even numbers return 'Odd'. This inverts the mathematical definition.

**Suggestion:**

Change 'if num % 2 == 1:' to 'if num % 2 == 0:', or swap the string literals so that it returns 'Odd' for odd numbers and 'Even' for even numbers.

### 2. Code Quality

- **Severity:** Low
- **Line:** 1

**Issues:**

- Function lacks type hints, reducing code clarity.

**Suggestion:**

Add type hints, e.g., 'def check_even(num: int) -> str:'.

---

### 3. Code Quality

- **Severity:** Low
- **Line:** 1

**Issues:**

- No input validation ensures 'num' is an integer. Passing a float (e.g., 2.5) would still return ‘Even’/‘Odd’ incorrectly, as 2.5 % 2 = 0.5, which is neither ==0 nor ==1. Passing a string would raise a TypeError.

**Suggestion:**

Add an assertion or explicit check: 'if not isinstance(num, int): raise TypeError(“num must be an integer”)'. Alternatively, validate and handle non-integer inputs appropriately.
